Show HN: drive.io — The missing relay layer for AI agents (99% token reduction)

---

Every major agent framework — AutoGen, CrewAI, LangGraph — has solved the single-agent experience. What’s missing is the space *between* agents: how a 100KB dataset travels from one agent to another without eating 27k tokens of context at every hop.

Today’s default is raw inline transfer: pasting file content directly into the next agent’s prompt. This is expensive, slow, and overflows context windows (100KB is ~20% of GPT-4o's window before any processing happens). S3 presigned URLs help, but a 500-character URL still tokenizes to ~68 tokens. It's a hack, not a protocol.

---
WHAT I BUILT
---

drive.io is a networked artifact relay for agent workflows. The core primitive: any payload — JSON, CSV, code, images — becomes a 7-token pointer URL via a single REST call. Agents pass references, not content.

  POST https://drive.io/api/upload
  → { "url": "https://drive.io/c/N37X6P9R2Z", "tiers": ["L0", "L1", "L2"] }

---
TIERED RETRIEVAL (O(1) Planning)
---

Most agent interactions don't require the full payload. Inspired by OpenViking, drive.io automatically generates three abstraction levels on upload:

  L0 — Abstract (~100 tokens): One-sentence summary for relevance checks.
  L1 — Overview (~2k tokens): Technical schema/headers for planning passes.
  L2 — Details: The full raw content, fetched only when necessary.

Usage: `GET https://drive.io/c/N37X6P9R2Z?tier=L1`

By fetching L1 for planning instead of L2, you save an additional 92% on token overhead for a 100KB file. Real-world savings are often higher than the headline benchmarks suggest.

---
HONEST TRADEOFFS
---

* Latency: ~30ms overhead per hop. In a 10-step pipeline, you pay ~300ms in wall-clock time to save $0.50+ in tokens.
* Outbound HTTP: Receiving agents must be able to make external calls.
* Tokenizer Variance: Numbers reflect OpenAI's cl100k_base. Claude/Gemini benchmarks will differ slightly.
* Encryption: End-to-end encryption adds minor serialization cost.
